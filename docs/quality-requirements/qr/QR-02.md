# QR-02: Run The Checks On The Critical Modules From A Clean Checkout

A developer runs the checks that cover the card generation, the review scheduler, and the frontend entry point from a clean checkout, without an LLM key, and a change that breaks one of them fails the checks.

- **Status:** Active
- **Characteristic:** Maintainability
- **Sub-characteristic:** Testability
- **Business importance:** High
- **Technical risk:** Medium

## Scenario

### Source

A team member, or an instructor reviewing the course work.

### Stimulus

They change [`backend/app/generation.py`](https://github.com/itpd-2026-team-5/team-5-sentence-card-generator/blob/main/backend/app/generation.py), [`backend/app/study.py`](https://github.com/itpd-2026-team-5/team-5-sentence-card-generator/blob/main/backend/app/study.py), or the frontend entry point [`frontend/src/main.tsx`](https://github.com/itpd-2026-team-5/team-5-sentence-card-generator/blob/main/frontend/src/main.tsx), and run the checks.

### Environment

A clean checkout with no `.env`, no LLM API key, and no network access to an LLM provider, on a laptop or in the "Product checks" CI workflow.

### Artifact

The backend test suite in `backend/tests/`, the frontend type-check and build, and the three modules above.

### Response

The checks shall run without a real LLM, and shall fail when a change breaks the duplicate check, the sentence checks, the per-deck limits, or the scheduling in those modules, or breaks the frontend's compilation.

### Response Measure

`uv run pytest` in `backend/` and `npm run build` in `frontend/` finish in under 3 minutes together on a clean checkout with no key; and each of these deliberate breaks makes at least one of them fail: removing the duplicate check in `generation.py`, removing the character bounds check in `generation.py`, ignoring a deck's daily new-card limit in `study.py`, and a type error in `main.tsx`.

## QRT-01

The product's checks run from a clean checkout without an LLM key, and a change that breaks one of the critical modules fails them.

- **Status:** Active
- **Level:** CI
- **Runs at:** the `Test` step of the `backend` job and the `Type check` and `Build` steps of the `frontend` job in [`.github/workflows/product.yml`](https://github.com/itpd-2026-team-5/team-5-sentence-card-generator/blob/main/.github/workflows/product.yml), on every pull request and on `main`.

### Procedure

1. Push to a pull request or to `main`; the `Product checks` workflow checks the commit out fresh, with no `.env` and no secrets.
2. The `backend` job runs `uv run pytest`, whose suite covers `backend/app/generation.py` (the duplicate check and the sentence checks) and `backend/app/study.py` (the per-deck limits and the scheduling) with a fake LLM.
3. The `frontend` job runs `npm run typecheck` and `npx vite build`, which compile `frontend/src/main.tsx` and everything it imports.
4. Read the run's result and the durations of those three steps on the run's page.

**Pass when:** the `backend` and `frontend` jobs are green and the `Test`, `Type check`, and `Build` steps take under 3 minutes together.
