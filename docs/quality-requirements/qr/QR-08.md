# QR-08: Run A Self-Hosted Deployment On Linux

An operator can install and run the core workflow on a Linux virtual machine using the documented prerequisites and configuration.

- **Status:** Active
- **Characteristic:** Flexibility
- **Sub-characteristic:** Installability
- **Business importance:** Medium
- **Technical risk:** Medium
- **Changed:**
  - 2026-10-31, per [DEC-101](../../decisions.md#dec-101): verify real generation and pronunciation from the deployment environment, rather than treating successful container startup or existing demo cards as completion of the core task.

## Scenario

### Source

An operator with access to a Linux virtual machine.

### Stimulus

The operator follows the [run instructions](../../setup.md) to install and start the application from a clean checkout.

### Environment

A Linux virtual machine meeting the documented resource and software prerequisites, with a configured real LLM provider for the generation check.
The evidence records the distribution, version, Docker and Compose versions, and configuration; the current Ubuntu environment is recorded in the [deployment runbook](../../deployment.md#the-vm), while the supported minimum and remaining checks are carried in the [Week 5 follow-up](../../../reports/week-05/meeting-report.md#open-questions).

### Artifact

The deployment configuration, containers, persistence, and run instructions, constrained by [CON-06](../../product-vision.md#con-06) and [DEC-070](../../decisions.md#dec-070).

### Response

The operator shall be able to start the service on Linux and complete text import, word selection, real card generation, study, and shared-deck access without an operating-system-specific workaround outside the instructions.
From a browser reaching that deployment through its intended network, the learner shall be able to generate a new card through the configured LLM path and hear its pronunciation.

### Response Measure

On the recorded Linux environment, configuration validation and service startup succeed, the health endpoint responds successfully, and every core-workflow step completes.
The operator records the commands and prerequisites needed; no unrecorded installation step is required.
The evidence includes a newly generated card and observed playback from the deployment client; an existing seeded card, a successful health response, or provider access on a different development machine does not establish those results.
Persistence across restart is checked separately under [QR-07](QR-07.md).
