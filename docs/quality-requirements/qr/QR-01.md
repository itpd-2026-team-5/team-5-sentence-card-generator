# QR-01: Keep Unshared Decks And Keys From A Teacher

A teacher can read and correct only the decks a learner shared with them, and never sees a learner's unshared decks or API key.

- **Status:** Active
- **Characteristic:** Security
- **Sub-characteristic:** Confidentiality
- **Business importance:** High
- **Technical risk:** Medium

## Scenario

### Source

A signed-in teacher, through the interface or by sending requests to the API directly.

### Stimulus

The teacher asks for a deck, a card, or a text of a learner who shared one other deck with them.

### Environment

Normal operation, with the learner owning at least one shared deck and one unshared deck, and the learner using their own API key in their browser, per [`DEC-019`](../../decisions.md#dec-019).

### Artifact

The `backend`'s deck, card, text, and teaching endpoints, and every response the teacher's account receives.

### Response

The product shall return the shared deck and its cards, and shall answer every request for the unshared deck, its cards, or the learner's texts as if they did not exist.

### Response Measure

For every deck, card, and text endpoint called with the teacher's session against the learner's unshared items, the status is `404` in 100% of calls, and no response body to the teacher's account contains the learner's API key; this is the access check of [`TOS-03`](../../threshold-of-success.md#tos-03).
