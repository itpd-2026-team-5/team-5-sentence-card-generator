# ADR-005: Schedule Reviews With The FSRS Library In The Backend

- **Status:** Accepted
- **Created:** 2026-10-24
- **Updated:** 2026-10-24
- **Containers:** `backend`, `database`
- **Addresses:** [`FR-008`](../../functional-requirements/fr/FR-008.md), [`FR-009`](../../functional-requirements/fr/FR-009.md), [`QR-02`](../../quality-requirements/qr/QR-02.md)
- **Decision:** [`DEC-005`](../../decisions.md#dec-005), [`DEC-041`](../../decisions.md#dec-041), [`DEC-042`](../../decisions.md#dec-042)

## Context

Reviews are scheduled with an established spaced-repetition algorithm ([`DEC-005`](../../decisions.md#dec-005), [`CON-05`](../../product-vision.md#con-05)), with per-deck daily limits ([`DEC-041`](../../decisions.md#dec-041)) and separate counts for new, review, and again cards ([`DEC-042`](../../decisions.md#dec-042)).
A learner may study on a laptop and a phone, so the schedule has to be the same on both.

## Considered Options

- **The `fsrs` Python package in the backend, with each card's FSRS state stored as JSON next to its review.**
  One schedule for every device, and the algorithm is the one Anki uses.
- **FSRS in the browser.**
  Ratings would feel instant, but two devices could disagree about what is due, and the schedule would need syncing.
- **Our own simpler intervals, such as doubling.**
  Easy to write, but it is not the established algorithm the Customer asked for.

## Decision Outcome

Chosen option: the `fsrs` package in the backend, which stores each card's state with its review and builds the study queue over the chosen decks with their limits.
The interval each rating would give is computed by the backend and shown before the learner rates.

## Consequences

- **Maintainability:** the scheduler is one module, `backend/app/study.py`, tested with fixed clocks, which [`QR-02`](../../quality-requirements/qr/QR-02.md) names.
- **Cost:** every rating is a request to the backend, so studying needs a connection, as [`BND-02`](../../product-vision.md#bnd-02) already accepts.
