# ADR-007: Export Request Signals To OpenObserve

- **Status:** Proposed
- **Created:** 2026-11-07
- **Updated:** 2026-11-07
- **Containers:** `backend`
- **Addresses:** [FR-014](../../functional-requirements/fr/FR-014.md), [QR-10](../../quality-requirements/qr/QR-10.md)

## Context

The operator needs a per-request failure point and a five-minute P95 signal across staging and production. The product must work when collection is unavailable.

## Considered Options

- **OpenTelemetry OTLP to self-hosted OpenObserve:** standard histogram and structured log export, scoped by organization.
- **Only container logs:** simple, but cannot directly provide the histogram P95 series required by QR-10.

## Decision Outcome

Choose OpenTelemetry OTLP/HTTP export from the backend to separate OpenObserve organizations, enabled by configuration. Use route templates and a random request ID instead of path parameters or user data.

## Consequences

- **Analysability:** [SLI-01](../../observability.md#sli-01) and the log point can diagnose a failed request.
- **Cost:** deployment needs a second telemetry service and two organizations; exporter intervals delay visibility by a few seconds.
