# ADR-002: Keep The Learner's Own Key In The Browser

- **Status:** Accepted
- **Created:** 2026-10-24
- **Updated:** 2026-10-24
- **Containers:** `frontend`, `backend`
- **Addresses:** [`FR-003`](../../functional-requirements/fr/FR-003.md), [`FR-005`](../../functional-requirements/fr/FR-005.md), [`QR-01`](../../quality-requirements/qr/QR-01.md), [`QR-05`](../../quality-requirements/qr/QR-05.md)
- **Decision:** [`DEC-019`](../../decisions.md#dec-019), [`DEC-027`](../../decisions.md#dec-027), [`DEC-028`](../../decisions.md#dec-028)

## Context

A learner may pay for sentences with their own LLM key instead of the service's key, and that key must never reach the service or a teacher ([`DEC-019`](../../decisions.md#dec-019)); any provider may be used, not only Anthropic ([`DEC-027`](../../decisions.md#dec-027)).
The prompt, the learner's known words, and the checks on each sentence live in the `backend`, and a teacher who rewrites a learner's card must not use the learner's key.

## Considered Options

- **The backend builds the request, the browser sends it, and the backend checks the answer.**
  The backend answers a generate request with `409 needs_llm` and the request it would have sent; the browser sends that request to the provider with the key it keeps, and posts the answer back for the backend to check and save.
- **The learner gives the key to the backend, which stores it encrypted.**
  One code path for both keys, but the service would hold the key, which [`DEC-019`](../../decisions.md#dec-019) rules out.
- **The browser does everything with its own key, including the prompt and the checks.**
  The key stays local, but the prompt and checks would exist twice, in Python and in TypeScript, and drift apart.

## Decision Outcome

Chosen option: the backend builds the request and the browser sends it, because the key never leaves the browser while the prompt and the checks stay in one place.
The key, the provider, the address, and the model are kept in the browser's local storage; the backend never receives them.

## Consequences

- **Security:** the learner's key is never in a request to the backend or in a response to anyone, which [`QR-01`](../../quality-requirements/qr/QR-01.md) checks for a teacher's account.
- **Reliability:** a provider error in the browser leaves the backend's state unchanged, because nothing is saved until the answer is posted back; [`QR-05`](../../quality-requirements/qr/QR-05.md) covers the learner's work on a failure.
- **Cost:** with the learner's key, the browser sends one request at a time, so a failed sentence is not retried automatically, and the key is lost when the learner clears their browser data.
